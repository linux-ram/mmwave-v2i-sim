\begin{abstract}
We present an open-source simulator for millimeter-wave vehicle-to-infrastructure (V2I) link-layer research.
The tool integrates map-matched mobility, geometric line-of-sight channel abstraction, runtime-selectable scheduling,
and two-dimensional resource-block packing (2DRBP) in a single self-contained desktop application.
A deterministic \texttt{sim\_engine} drives per-timestep snapshots for headless batch studies and interactive playback,
while a parallel research path exposes YAML-configured city presets, dual-band (28/39\,GHz) radio models, and pluggable schedulers.
Session exports bundle JSON manifests, CSV trim-loss traces, and an embedded NumPy workspace for offline analysis.
The design targets reproducible experimentation without external licensed runtimes or opaque native packing binaries.
\end{abstract}

\section{Introduction}
Millimeter-wave V2I systems couple urban mobility, directional beams, blockage, and time--frequency resource allocation.
Link-layer studies require an end-to-end loop: vehicle positions and routes, beam and LoS state, service-block demand,
packing into a normalized resource grid, and metrics such as trim loss and utilization over many timesteps.
Few open tools expose this loop with both an interactive map view and machine-readable session artifacts.

This simulator closes that gap with a modular Python architecture, a PySide6 desktop GUI, and documented validation sweeps.
The default path (\texttt{sim\_engine}) emphasizes reproducible 2DRBP experiments; an extended \texttt{core}/\texttt{channel}/\texttt{mobility} stack supports comparative studies with city-scale presets and alternative schedulers.

\subsection{Contributions}
The release provides:
\begin{itemize}
  \item A \textbf{unified timestep engine} with fixed-seed determinism, bundled vehicular routes, and per-step resource service block (RSB) generation.
  \item \textbf{In-process 2DRBP packers} (Guillotine, Shelf, MaxRects) with trim-loss reporting and density sweeps over vehicle counts $\{1,2,5,10,50\}$.
  \item A \textbf{dual-path architecture}: interactive \texttt{sim\_engine} for teaching and prototyping, plus YAML-driven research scenarios (Boston, San Francisco, RTP presets; dual-band channel; Max-CQI, proportional-fair, latency-aware scheduling).
  \item \textbf{Self-contained distribution}: \texttt{pip install -e ".[dev,gui]"} on macOS, Windows, and Linux; optional vendored C++ rectangle-bin sources for parity checks without a mandatory external executable.
  \item \textbf{ZIP session export} (\texttt{manifest.json}, CSV, \texttt{session.npz}) for spreadsheets, notebooks, and third-party analysis tools.
\end{itemize}

\section{Simulator Architecture}
The default engine maintains a \texttt{SimSession} keyed by vehicle count and random seed.
Each \texttt{step()} advances mobility along precomputed routes, updates LoS probability along polylines, assigns RSB dimensions (stochastic per step so trim loss varies even at low vehicle counts), and invokes the selected packing algorithm.
Snapshots feed the GUI and headless CLIs alike, ensuring identical numerics whether the user runs \texttt{--gui}, \texttt{--config}, or \texttt{--batch}.

The research path loads \texttt{scenario\_*.yaml} files through a schema-validated configuration layer.
Phases (warm-up, data collection) gate KPI logging; the channel module applies geometric blockage and optional codebook versus ideal beamforming modes at 28 and 39\,GHz.
Both paths share validation scripts that emit JSON reports under \texttt{artifacts/validation/}.

\section{Mobility and Channel Models}
\textbf{Mobility.} The GUI path uses OSM-style bundled routes with configurable vehicle counts (up to 50 in the default scenario).
The research path adds open-license city presets with rectangular extents and synthetic lane grids or CSV map-matched traces.

\textbf{Channel.} Route-based LoS probability drives beam coloring on the aerial map.
The extended channel model combines 3GPP-inspired path loss with geometric LOS/NLOS classification, dual-band carrier frequencies, and a switchable beam mode (\texttt{codebook} vs.\ \texttt{ideal}) for sensitivity analysis.
These abstractions trade full TR~38.901 cluster models for transparency and fast iteration---appropriate for link-layer allocation studies rather than PHY waveform design.

\section{Resource Allocation and 2DRBP}
Vehicles request normalized resource blocks each timestep.
The packer places axis-aligned rectangles into a fixed grid; unplaced demand contributes to \textbf{trim loss}, the primary comparative metric across vehicle densities.
Three algorithms ship in-process: Guillotine splits, Shelf rows, and MaxRects free-rectangle management---each selectable at runtime without recompilation.

Batch mode sweeps \texttt{nVehicle} over five standard counts with multiple trials per point, producing mean and standard deviation of trim loss for regression against published V2I allocation curves.
Scheduler plugins on the research path allocate users before packing when studying fairness or latency policies.

\subsection{Research Extensions}
City-preset demos (\texttt{scripts/demo\_city\_presets.py}) exercise the legacy stack independently of the GUI routes.
Researchers can mix presets, beam modes, and schedulers in one YAML file while the desktop app remains the fastest on-ramp for 2DRBP visualization.

\section{Reproducibility and Session Export}
Fixed seeds yield bit-stable timestep sequences.
\texttt{python scripts/generate\_readme\_assets.py} renders figure previews; \texttt{bash scripts/build\_paper.sh} rebuilds this document.
Completed GUI runs export a ZIP archive containing structured metadata, per-step trim-loss CSV (Excel-friendly), JSONL event logs, and \texttt{session.npz} reloadable via \texttt{load\_workspace\_npz()}.
CI validates packing parity (including Linux-built native checks) and regenerates the PDF on \texttt{paper/} changes.

\section{Conclusion}
The simulator is a self-contained mmWave V2I link-layer testbed: deep enough for allocation and mobility studies, yet installable in minutes for labs and independent projects.
By unifying visualization, batch sweeps, dual-band research hooks, and portable session artifacts, it lowers the cost of credible, repeatable V2I experiments without tying results to a single vendor toolchain.
